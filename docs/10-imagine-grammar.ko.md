# imagine 선언의 문법

치즈기여어는 TypeScript의 슈퍼셋입니다. 여러분이 쓰던 TypeScript 문법은
그대로 두고, 그 위에 `imagine`이라는 확장 키워드 하나를 얹었습니다.

얹은 것이 하나뿐이라도, "어디까지가 치즈기여어의 문법이고 어디부터가
TypeScript인가"는 분명해야 합니다. 그렇지 않으면 여러분이 쓴 코드가 어느 쪽
규칙으로 읽힐지 알 수 없으니까요. 이 문서는 그 경계를 정확히 정합니다.

## `imagine`은 예약어가 아닙니다

먼저 좋은 소식부터. `imagine`은 **예약어가 아닙니다.** 여러분의 기존
TypeScript 코드에 `imagine`이라는 이름의 변수나 함수가 있어도 아무 문제가
없습니다.

```typescript
const imagine = createPreview();

imagine();
imagine.preview();
object.imagine();
```

이 코드는 치즈기여어에서도 평범한 TypeScript로 읽힙니다.

그럼 컴파일러는 "선언으로 쓴 `imagine`"과 "이름으로 쓴 `imagine`"을 어떻게
구분할까요?

### 규칙: 문장 첫머리의 `imagine`은 선언으로 봅니다

문장이 시작되는 자리(또는 클래스 본문에서 멤버가 시작되는 자리)에서
`imagine`을 만나면, 컴파일러는 **일단 치즈기여어 선언이라고 판단**합니다.

다만 바로 뒤에 오는 토큰이 "표현식을 이어갈 수 있는 것"이면 판단을
취소하고 평범한 이름으로 되돌립니다. 취소시키는 토큰은 다음과 같이 정해져
있습니다.

| 분류 | 토큰 |
|---|---|
| 호출·접근 | `(` `.` `?.` `[` `<` 태그드 템플릿의 `` ` `` |
| 대입·연산 | `=`와 복합 대입, 산술·비교·논리 연산자, `??` `?` `:` |
| 타입 연산 | `as` `satisfies` `instanceof` `in` |
| 후위·단언 | `++` `--` `!` |
| 문 경계 | `;` `,` `)` `]` `}` 그리고 파일의 끝 |
| 줄바꿈 | `imagine`과 다음 토큰 사이의 줄바꿈 |

마지막 줄의 "줄바꿈"이 조금 의외일 수 있습니다. 이런 코드 때문입니다.

```typescript
declare const imagine: unknown;

imagine
function next(): void {}
```

여기서 `imagine`은 그 자체로 하나의 문장이고, 다음 줄의 `function next()`는
별개의 선언입니다. 줄바꿈을 취소 신호로 두지 않으면 치즈기여어가 이 둘을
하나의 `imagine function`으로 잘못 붙여 읽게 됩니다.

> TypeScript에도 같은 성격의 규칙이 있습니다. `async` 뒤에 줄바꿈이 오면
> 그 `async`는 `async function`의 일부가 아니라 그냥 이름으로 취급됩니다.

### 한 번 선언으로 정하면 되돌리지 않습니다

이 부분이 중요합니다. 위 표에 없는 토큰이 뒤따라오면, 컴파일러는 그것을
**치즈기여어 선언으로 확정**합니다. 그리고 확정한 뒤에는 "역시 아닌가 보다"
하고 물러서지 않습니다.

그래서 다음 코드는 조용히 넘어가지 않고 오류가 됩니다.

```typescript chz
imagine imagine function f(): void {}
//      ^ CHZ1001: 'imagine' 다음에는 function 또는 class가 와야 합니다
```

첫 번째 `imagine` 뒤에 온 것은 `imagine`이라는 이름이고, 이것은 취소 목록에
없습니다. 그래서 선언으로 확정되고, 그다음에 와야 할 `function`이나 `class`가
없으므로 두 번째 `imagine` 위치에서 오류가 납니다.

물러서지 않기로 한 이유는 간단합니다. 물러서면 오타가 오류가 아니라 그냥
평범한 코드로 남아 버립니다. 여러분이 `imagine functon`(오타)이라고 썼을 때,
"이건 치즈기여어 선언이 아니네" 하고 넘어가는 컴파일러보다 "여기서 오타가
났습니다" 하고 알려주는 컴파일러가 낫습니다.

### 겉모습이 같아도 이름은 이름입니다

유니코드 이스케이프로 쓴 `imagine`은 값으로는 `imagine`과 같은
식별자이지만, 치즈기여어는 이것을 선언으로 보지 않습니다. **원본에 적힌 글자가
정확히 `imagine`일 때만** 선언 후보가 됩니다.

## imagine 함수

가장 기본이 되는 형태입니다.

```typescript chz
/// coffee.chz.ts
imagine function 아메리카노_가격(잔수: number): number {
  requirements(`
    아메리카노 한 잔은 4500원입니다.
    5잔 이상 주문하면 전체 금액의 10%를 할인합니다.
  `);

  ensure(아메리카노_가격(1) === 4500);
  ensure(아메리카노_가격(5) === 20250);
}
```

함수의 이름, 매개변수, 반환 타입은 전부 **평범한 TypeScript**입니다.
치즈기여어가 따로 해석하지 않고 TypeScript에게 그대로 맡깁니다. 그래서 제네릭도,
복잡한 객체 타입도 여러분이 아는 그대로 쓸 수 있습니다.

```typescript chz
imagine function 감싸기<T>(값: T): Promise<{ 값: T; 시각: Date }> {
  requirements(`값과 현재 시각을 함께 담아 반환합니다.`);
}
```

### `export imagine`

바깥에서 쓸 함수라면 `export`를 붙입니다.

```typescript chz
export imagine function 데미지_계산(공격력: number, 방어력: number): number {
  requirements(`공격력에서 방어력을 빼되, 최소 1은 보장합니다.`);
}
```

`export`를 붙였는지 여부는 단순한 표시가 아닙니다. **소스에서 `export`한 것만
바깥에 노출됩니다.** `export`가 없는 imagine 심볼도 똑같이 구현되지만, 그 파일
안에서만 쓰입니다. 이 규칙은 [20 문서](20-module-resolution.ko.md)의 모듈 노출
규칙과 같습니다.

### `export default`는 쓸 수 없습니다

```typescript chz
export default imagine class C {}
//     ^ CHZ1005: imagine 선언에는 쓸 수 없는 modifier입니다
```

`declare`와 `abstract`도 마찬가지로 거부됩니다.

`export default`를 막는 이유는 **이름이 없기 때문**입니다. 치즈기여어는 심볼
이름을 여러 곳에서 열쇠로 씁니다 — 구현이 저장되는 파일 이름, 다시 만들지 말지
판단하는 캐시 키, 어떤 심볼이 어떤 심볼을 필요로 하는지 적어 두는 의존성
그래프의 노드 이름까지 전부 이름에 묶여 있습니다. 이름이 없으면 이 열쇠들을
만들 수 없습니다.

default로 내보내고 싶다면 이름을 붙여 선언한 뒤, 사람이 쓰는 코드에서 다시
내보내면 됩니다.

```typescript chz
export imagine function 데미지_계산(공격력: number, 방어력: number): number {
  requirements(`공격력에서 방어력을 빼되, 최소 1은 보장합니다.`);
}

export default 데미지_계산;
```

## imagine 클래스

클래스도 같은 방식으로 선언합니다. 클래스 본문에는 세 가지를 쓸 수 있습니다.

```typescript chz
/// gacha.chz.ts
imagine class 뽑기함 {
  // (1) 클래스 전체에 대한 요구사항
  requirements(`
    10연차 뽑기를 관리합니다.
    10번째 뽑기에서는 반드시 레어 이상이 나와야 합니다.
  `);

  // (2) 구현이 필요한 프로퍼티
  imagine readonly 남은횟수: number {
    requirements(`이번 판에 남은 뽑기 횟수입니다.`);
  }

  // (3) 구현이 필요한 메서드
  imagine 뽑기(): "노말" | "레어" | "에픽" {
    requirements(`한 번 뽑고 결과 등급을 반환합니다.`);

    ensure("10연차의 마지막은 레어 이상입니다.", () => {
      const 함 = new 뽑기함();
      for (let i = 0; i < 9; i++) 함.뽑기();

      assert(함.뽑기() !== "노말");
    });
  }
}
```

여기에 더해, 클래스 본문에는 **사람이 직접 구현한 평범한 TypeScript 멤버**도
그대로 쓸 수 있습니다. 이미 답을 알고 있는 계산이라면 LLM에게 맡기지 말고
직접 적는 편이 낫습니다.

### imagined 프로퍼티의 모양

프로퍼티는 조금 특이하게 생겼습니다. 타입 뒤에 중괄호가 오고 그 안에 계약을
적습니다.

```typescript chz
imagine readonly 남은횟수: number {
  requirements(`이번 판에 남은 뽑기 횟수입니다.`);
}
```

이것은 TypeScript에는 없는 모양입니다. 보통의 프로퍼티라면 `남은횟수: number;`로
끝나고 중괄호가 올 자리가 아니니까요. 치즈기여어가 직접 소유하는 문법이며,
`static`이나 `readonly` 같은 modifier를 앞에 붙일 수 있습니다.

## 계약 본문에는 계약만 씁니다

`imagine` 선언의 중괄호 안, 그리고 클래스 본문의 계약 자리에는
**`requirements(...)`와 `ensure(...)`만** 쓸 수 있습니다.

```typescript chz
imagine function f(): number {
  requirements(`1을 반환합니다.`);

  const expected = 1; // CHZ1004: 여기에는 쓸 수 없습니다
  return expected;    // CHZ1004
}
```

`imagine` 선언은 "무엇이 필요한지"를 적는 자리이지 "어떻게 만드는지"를 적는
자리가 아닙니다. 구현은 realize 단계에서 LLM이 채웁니다. 그래서 여기에 적은
구현 코드는 어차피 쓰이지 않습니다.

문제는 **쓰이지 않는다는 사실이 눈에 보이지 않는다**는 점입니다. 예전에는 이런
문장을 조용히 무시했기 때문에, 계약을 적었다고 생각한 코드가 사실은 아무 데도
반영되지 않는 일이 생겼습니다. 이제는 오류로 알려 드립니다.

단, **시나리오 `ensure`의 콜백 안은 예외**입니다. 그 안은 실제로 실행되는
테스트이므로 평범한 TypeScript를 자유롭게 쓸 수 있습니다.

```typescript chz
imagine function f(): number {
  ensure("1을 반환합니다.", () => {
    const result = f();      // 여기는 괜찮습니다
    assert(result === 1);
  });
}
```

## `requirements`의 인자

`requirements(...)`에는 **문자열 하나만** 넘길 수 있습니다. 따옴표 문자열이나,
`${...}` 치환이 없는 백틱 문자열이어야 합니다.

```typescript chz
imagine function f(): void {
  requirements(`값 ${limit}까지 처리합니다.`);
  //           ^ CHZ2001: 치환이 들어간 템플릿 문자열은 쓸 수 없습니다
}
```

변수를 참조하거나, 문자열을 `+`로 잇거나, 인자를 여러 개 넘기는 것도 모두
같은 이유로 막습니다.

`requirements`에 적은 글은 **realize 단계에서 LLM에게 그대로 전달되는
프롬프트**입니다. 프로그램이 실행되기 한참 전, 코드를 만드는 시점에 읽히는
값이라는 뜻입니다. 그래서 실행 중에 정해지는 값이 끼어들 자리가 없습니다.

또 하나. 치즈기여어는 "요구사항이 바뀌었으니 다시 만들어야 한다"를 판단할 때
이 글의 해시를 씁니다. 해시는 소스만 보고 계산할 수 있어야 하므로, 실행해
봐야 알 수 있는 값이 섞이면 곤란합니다.

`requirements`는 한 선언에 한 번만 쓸 수 있습니다. 여러 문단이 필요하면 하나의
문자열 안에서 나누어 적으십시오.

## `ensure`의 두 가지 모양

`ensure`는 사람이 직접 적는 합격 기준입니다. 두 가지 모양이 있습니다.

**하나. 조건식으로 적기.**

```typescript chz
ensure(아메리카노_가격(1) === 4500);
ensure(아메리카노_가격(5) === 20250, "5잔부터 10% 할인이 적용됩니다.");
```

두 번째 인자인 설명은 생략할 수 있고, 적는다면 **고정된 문자열**이어야 합니다.

**둘. 시나리오로 적기.**

준비 과정이 필요하거나 확인할 것이 여러 개라면 이렇게 씁니다.

```typescript chz
ensure("빈 장바구니의 합계는 0원입니다.", () => {
  const 담은것 = new 장바구니();

  assert(담은것.합계() === 0);
  assert(담은것.개수() === 0);
});
```

설명을 먼저 쓰고, 인자가 없는 함수를 뒤에 씁니다. 함수 안에서는 엔진이
제공하는 `assert()`를 쓸 수 있습니다.

자연어만 적어 두는 `ensure("빨라야 합니다")` 같은 형태는 쓸 수 없습니다.
말로 하는 설명은 `requirements`의 몫이고, `ensure`는 반드시 실행해서
참·거짓을 가릴 수 있어야 합니다.

## 아직 지원하지 않는 것

- **`.chz.tsx`** — JSX가 들어간 치즈기여어 파일은 아직 받지 않습니다.
  조용히 `.ts`로 읽어 버리면 `<`를 제네릭으로 오해하는 등 엉뚱한 오류가
  나므로, 명시적으로 거부합니다(CHZ1006). JSX가 필요하면 평범한 `.tsx`
  파일로 분리하고, 치즈기여어 선언은 `.chz.ts`에 두십시오.
- **`imagine resource`, `imagine var`** — 자리는 예약해 두었지만 아직 문법이
  열려 있지 않습니다(CHZ1008).

## 오류 코드 읽는 법

치즈기여어가 알려주는 오류에는 앞자리로 종류가 구분되어 있습니다.

| 앞자리 | 무엇에 대한 오류인가 |
|---|---|
| `CHZ1xxx` | 치즈기여어의 문법 — `imagine` 선언의 모양 |
| `CHZ2xxx` | 계약의 모양 — `requirements`와 `ensure`의 인자 |
| `CHZ3xxx` | realize·프로파일 등 정적 규칙 |
| `TSxxxx` | TypeScript가 알려준 오류 — 치즈기여어가 손대지 않고 그대로 전달합니다 |

모든 오류 메시지에는 **어떻게 고치면 되는지**가 함께 적혀 있습니다. 메시지가
가리키는 위치는 언제나 여러분이 작성한 `.chz.ts` 파일의 줄·칸 번호입니다.
치즈기여어가 내부적으로 코드를 변형해서 TypeScript에게 넘기더라도, 위치는
원본 기준으로 되돌려 알려 드립니다.
